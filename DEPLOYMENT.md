# Deployment Checklist — DA-MIMAROPA Fleet Management System

Use this checklist for the first production deployment and for later updates.
Tick each box on the production server. Never copy the development `.env` to production.

---

## 1. Server requirements

- [ ] **PHP 8.4.1 or newer** (the installed Symfony 8.1 components need it; `composer install` fails on PHP 8.3). Development and testing used PHP 8.4.25.
- [ ] **PHP extensions**:
  - Laravel: `ctype`, `filter`, `hash`, `mbstring`, `openssl`, `session`, `tokenizer`, `json`, `pcre`
  - Database: `pdo_mysql`
  - Excel and Word report exports: `dom`, `xml`, `xmlreader`, `xmlwriter`, `simplexml`, `libxml`, `zip`, `zlib`, `gd`, `iconv`
  - File uploads: `fileinfo`
- [ ] **MySQL 8.0 or newer**, with InnoDB and `utf8mb4`. Development used MySQL 9.7.
- [ ] **Nginx or Apache** with its document root set to the project's **`public/`** folder, never the project root.
- [ ] **HTTPS certificate** installed. Port 80 redirects to HTTPS.
- [ ] **Composer 2**.
- [ ] **Node.js 20.19+ or 22.12+ and npm** (Vite's minimum). These are only needed to build the CSS and JS. You can also build elsewhere and upload `public/build/`.
- [ ] **Upload limits** of at least `upload_max_filesize = 8M` and `post_max_size = 10M` in PHP, and `client_max_body_size 10M` in Nginx.
  - Avatars, vehicle photos and licence images allow up to 5 MB.
  - The app logo allows up to 4 MB.
- [ ] The server clock is correct. The app runs on `Asia/Manila` time (`config/app.php`).

## 2. Production `.env`

Start from the template, generate a key, then edit the values:

```bash
cp .env.example .env
php artisan key:generate
```

| Key | Production value | Why |
|---|---|---|
| `APP_ENV` | `production` | Turns on production behaviour. |
| `APP_DEBUG` | `false` | **Critical.** When `true`, error pages show code, queries and settings to anyone. |
| `APP_KEY` | generated by `key:generate` | Encrypts sessions and data. Back it up; never change it after go-live. |
| `APP_URL` | `https://your-real-domain` (no trailing slash) | Uploaded vehicle photos, avatars and licence images get their web address from it. If it is wrong, those images appear broken. |
| `LOG_STACK` / `LOG_LEVEL` / `LOG_DAILY_DAYS` | `daily` / `warning` / `30` | One log file per day, without debug noise, kept for 30 days. |
| `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` | dedicated database and user, **strong password** | Never use `root` or an empty password. |
| `SESSION_DRIVER` | `database` | Already the default. |
| `SESSION_SECURE_COOKIE` | `true` | Cookies are only sent over HTTPS. |
| `SESSION_ENCRYPT` | `true` | Session contents are encrypted. |
| `SESSION_LIFETIME` | `120` (minutes) | Adjust to your office policy. |
| `MAIL_MAILER` | `smtp` | Needed for "Forgot password" emails. With `log`, the Forgot Password page tells users to contact an administrator instead. |
| `MAIL_HOST` / `MAIL_PORT` / `MAIL_USERNAME` / `MAIL_PASSWORD` / `MAIL_SCHEME` | your agency's SMTP details | Port 587 usually uses STARTTLS (`MAIL_SCHEME=null`). Port 465 uses `MAIL_SCHEME=smtps`. |
| `MAIL_FROM_ADDRESS` | e.g. `no-reply@your-domain` | Sender address for system emails. |
| `QUEUE_CONNECTION` | `database` | The app has no queued jobs today, so no queue worker is needed. |

Keep a secure, offline copy of the final `.env`, especially `APP_KEY`.

## 3. First deployment

1. **Create the database and its user.** Run this in MySQL as an administrator, and change the password:
   ```sql
   CREATE DATABASE fleetdb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'fleet_app'@'127.0.0.1' IDENTIFIED BY 'CHANGE-ME-strong-password';
   GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES ON fleetdb.* TO 'fleet_app'@'127.0.0.1';
   FLUSH PRIVILEGES;
   ```
   The host part (`127.0.0.1`) must match how the app connects (`DB_HOST`). If MySQL runs on a separate server, use the app server's IP address instead.
2. **Get the code and install dependencies:**
   ```bash
   git clone https://github.com/az-mis/FleetMonitoring.git
   cd FleetMonitoring
   composer install --no-dev --optimize-autoloader
   ```
3. **Configure** `.env` as described in section 2.
4. **Build the frontend:**
   ```bash
   npm ci
   npm run build
   ```
   Make sure **`public/hot` does not exist** on the server. That file only exists while `npm run dev` is running. If it is present, every page tries to load styles from the developer's machine and appears unstyled.
5. **Create the tables:**
   ```bash
   php artisan migrate --force
   ```
6. **Link public storage** so photos, avatars and the logo display:
   ```bash
   php artisan storage:link
   ```
7. **Create the first Super Admin.** Do **not** run `php artisan db:seed`; its sample-data seeders refuse to run in production anyway:
   - `DatabaseSeeder` (a "Test User" account and fake vehicles) and `SuperAdminSeeder` (`superadmin@fleetmonitoring.test` with the password `password`) stop with "Refusing to seed … in production".
   - `QaSeeder` creates QA accounts with the password `password`. It refuses to run unless the database name ends in `_qa`.

   Run (it asks for the password at a hidden prompt, twice, then shows how many characters you typed so you can confirm):
   ```bash
   php artisan fleet:create-super-admin --name="Full Name" --email="name@your-domain"
   ```
   Or add `--generate` to have it make a strong password and show it once. Passwords need at least 12 characters with letters and numbers.

   Create Admin and Driver accounts afterwards from inside the app. Every Admin must have a location.
8. **Cache configuration, routes and views** for speed:
   ```bash
   php artisan optimize
   ```
9. **Set folder permissions.** The web server user (often `www-data`) must be able to write to `storage/` and `bootstrap/cache/`:
   ```bash
   chown -R www-data:www-data storage bootstrap/cache
   chmod -R ug+rwX storage bootstrap/cache
   ```
10. **Configure the web server.** For Nginx, set the root to `/path/to/FleetMonitoring/public`, forward PHP to PHP-FPM, and allow 10 MB uploads:
    ```nginx
    client_max_body_size 10M;
    ```
    The app itself sends the security headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and `Strict-Transport-Security` over https), so they work on Nginx and Apache alike. Headers the web server already sets are left alone.
11. **Behind a reverse proxy or load balancer?** If HTTPS ends at the proxy, set `TRUSTED_PROXIES` in `.env` to the proxy's IP address(es), comma-separated, or `*` for the one directly in front. Otherwise links come out as `http://`, and every visitor shares the proxy's address in the rate limits. Leave it empty when the web server itself serves HTTPS.
12. **Move existing licence photos to private storage** (only when you copied data from another server; a fresh install has none):
    ```bash
    php artisan fleet:secure-licence-photos
    ```
13. Run the smoke test in section 6.

## 4. Updating an existing deployment

```bash
php artisan down                      # maintenance page for users
# back up the database first (section 5)
git pull origin main
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan migrate --force
php artisan optimize:clear && php artisan optimize
php artisan up
```

## 5. Backups and recovery

- [ ] **Daily database backup**, kept off the server for at least 30 days. Example cron line:
  ```bash
  0 1 * * * mysqldump --single-transaction --routines --triggers --no-tablespaces --set-gtid-purged=OFF -u fleet_app -p'PASSWORD' fleetdb | gzip > /backups/fleetdb-$(date +\%F).sql.gz
  ```
  Prefer a MySQL option file (`~/.my.cnf`) over writing the password on the command line.
- [ ] **Back up `storage/app/public/` and `storage/app/private/`**. Public holds vehicle photos, avatars and the logo; private holds driver licence photos.
- [ ] **Keep a secure copy of `.env`.** Without `APP_KEY`, encrypted data and sessions cannot be read.
- [ ] **Practise a restore** into a separate database at least once before go-live, then every quarter:
  ```bash
  mysql -u root -p fleetdb_restore_test < fleetdb-YYYY-MM-DD.sql
  ```

## 6. Post-deployment smoke test

Sign in once as each role and check:

- [ ] The login page loads over **https** with the green styling (no unstyled page).
- [ ] **Super Admin:**
  - Dashboard, Admins, Content Settings and Reports open.
  - The Excel export downloads.
  - Uploading a logo works.
- [ ] **Admin:**
  - Only their own location's data is shown.
  - Approving a request issues a trip ticket number.
  - The trip ticket prints.
  - Fleet card expense and top-up work.
- [ ] **Driver:**
  - Dashboard and Travel History show their trips.
  - Reporting a vehicle issue works.
- [ ] **Public visitors:**
  - The Request a Vehicle form submits.
  - Check Status shows the reference code and, once approved, a working trip ticket link.
- [ ] **Mail works:** `php artisan fleet:mail-test you@your-domain` reports "Test email sent", and the email arrives.
- [ ] **Forgot password** sends an email, and the link resets the password.
- [ ] Trigger a 404 (for example `/does-not-exist`). It must show a simple error page, **not** a stack trace.
- [ ] `storage/logs/` contains no new errors.

## 7. Known open items (decide before or soon after go-live)

1. **Database hardening (needs a migration):**
   - Unique driver licence numbers. Remove duplicates first.
   - One completion record per trip.
   - Keep maintenance and inspection history instead of deleting it with the vehicle.
   - A trip-ticket number sequence table.
2. **Product questions:**
   - Vehicle Assigning saves on dropdown change.
   - Changing a fleet card's location clears its vehicle.
   - Default Approving Officer names are hard-coded.
   - Admins can lower odometer readings.
